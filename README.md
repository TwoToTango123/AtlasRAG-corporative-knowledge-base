# AtlasRAG — агентный RAG для корпоративной базы знаний

Исследовательский прототип на Python: гибридный поиск BM25 + multilingual E5,
поисковый агент с tool calling, реранжирование, ответы с проверяемыми цитатами
и отдельная оценка качества. Демокорпус — 12 документов вымышленной компании
(21 чанк); основной набор — 39 вопросов, включая 6 вопросов без ответа.

### Актуальные проверенные результаты

| Эксперимент | Результат | Граница вывода |
|---|---|---|
| Защита опор в финальном контексте | 10/12 → 12/12 правильных ответов; Recall@5 0,917 → 1,000 | 12 синтетических регрессий на тех же поисковых траекториях |
| Материализация цитат из исходных диапазонов | 97/97 посимвольно точных цитат; цитаты у 45/45 ответимых вопросов | Не гарантирует смысловую поддержку или правильность ответа |
| LLM-реранкер и BGE cross-encoder | nDCG@5 0,953 и 0,967; Recall@5 0,985 и 0,970 | 33 вопроса, одинаковые кандидаты; убедительного победителя нет |
| Проверки кода | 97 тестовых случаев pytest проходят | Это проверки реализации, не 97 независимых измерений качества |

Основные отчёты: [агент и single-pass](results/routerai_followup/findings.md),
[исправление контекста](results/repair_v2/findings.md),
[цитаты](results/context_citations/findings.md),
[проверка оценщика](results/assistant_review/findings.md).
Разметка ассистентская; независимого человеческого аудита и production-внедрения нет.
Исторические отчёты сохранены с фактическими датами и первоначальными оценками.
Сырые API-кеши, ключи, локальные индексы и личные артефакты не публикуются.

### Материалы и воспроизведение

Подготовка к собеседованию: [рассказ и 120 вопросов с ответами](docs/interview/AtlasRAG_собеседование.html)
или [Markdown](docs/interview/AtlasRAG_собеседование.md). Материал сверён с кодом
и отчётами 07.11.2026; содержит различия между реализованным и экспериментами.

Сравнить три варианта реранкинга на одинаковых кандидатах:

```powershell
.\.venv\Scripts\python.exe -m scripts.compare_rerankers
```

Скрипт сравнивает гибридный поиск без реранкинга, текущий LLM-реранкер
(`ATLAS_FAST_MODEL`) и локальный `BAAI/bge-reranker-v2-m3` на 33 вопросах с
ответами. Все варианты получают одни и те же 10 кандидатов и возвращают top-5;
HyDE, агент, генерация и LLM-судья отключены. Сравниваются Recall@5, MRR@5,
nDCG@5, время реранкинга и свежие API-токены. Первый запуск скачивает веса
cross-encoder. Его оценки не используются как шкала CRAG 0–10.

Отчёт: `results/rerankers/comparison.md` и `.json`. Ответы LLM кешируются рядом
в `llm_cache.jsonl`. При отсутствии API-ключа LLM-вариант помечается как
неизмеренный. `--skip-llm` позволяет явно отключить API, `--device cpu` выбрать
CPU, `--skip-cross-encoder` пропустить локальную модель. Время загрузки моделей
и поиска не входит в время реранкинга; для cross-encoder выполняется прогрев.

Полная оценка через RouterAI (ключ `ROUTERAI_API_KEY` в `.env`):

```powershell
.\.venv\Scripts\python.exe -m scripts.run_routerai_eval --phase pilot
.\.venv\Scripts\python.exe -m scripts.run_routerai_eval --phase full
```

Пилот проверяет факт, составной вопрос и вопрос без ответа. Полный запуск
проверяет все 39 вопросов сначала с GPT-OSS 120B, затем с DeepSeek Flash;
в обоих случаях вспомогательная модель — GPT-OSS 20B, судья — Qwen3.8 27B.
Успешные кейсы сохраняются по отдельности и при перезапуске пропускаются.
Сводка и детализация: `results/routerai_full/summary.md`, `.json` и каталоги кейсов.

Кеш, тарифы, выбранные хосты и журнал расходов хранятся в игнорируемом Git
каталоге `results/raw/routerai`. Бюджет по умолчанию — 90 ₽ на весь журнал,
неснижаемый остаток — 10 ₽. Перед каждым вызовом резервируется консервативная
оценка его максимальной стоимости по всем опубликованным хостам модели;
неопределённая сетевая ошибка сохраняет резерв. Только подтверждённые ошибки
ограничения частоты без списания повторяются до трёх раз с паузой; сетевые
таймауты автоматически не повторяются. После остальных ошибок дальнейшие
платные вызовы текущего экземпляра останавливаются.
Для одного журнала допускается только один процесс. Стоимость сверяется с
балансом RouterAI и `usage.cost`, токены учитываются отдельно по каждой модели.
Эти ограничения задаются полями `routerai_*` класса `Settings`.

AtlasRAG превращает массив корпоративных документов (регламенты, спецификации,
SLA, инструкции, договоры) в надёжного ассистента для ответов на вопросы. В
основе системы — **поисковый агент на базе LLM**: вместо жёсткого конвейера
«эмбеддинг → top-k → подстановка в промпт» модель сама планирует и
*корректирует* свой поиск — раскладывает вопрос на части, переформулирует слабые
запросы, оценивает найденные данные и решает, когда их достаточно для ответа.
Каждый ответ снабжается **ссылками на источники** и проходит **самопроверку на
обоснованность** для защиты от галлюцинаций.

LLM-слой не привязан к провайдеру. По умолчанию используется **Groq**:
`openai/gpt-oss-120b` для агента и генерации, `openai/gpt-oss-20b` для массовых
задач (HyDE, реранк, проверка обоснованности) и `qwen/qwen3.8-27b` как судья
при оценке. Через `ATLAS_LLM_PROVIDER=anthropic` система работает на Claude.
Эмбеддинги считаются локально (`multilingual-e5-small`). Ассистент отвечает на
русском языке.

## Зачем это бизнесу

| Проблема наивного RAG | Что делает AtlasRAG |
|---|---|
| Один эмбеддинг-поиск упускает точные токены (артикулы, коды ошибок) или перефразировки | **Гибридный поиск**: плотные эмбеддинги + BM25, объединённые через Reciprocal Rank Fusion |
| Один проход поиска не отвечает на составные вопросы | **Агентный цикл**: модель выполняет несколько целевых поисков и объединяет результаты |
| Поиск молча возвращает мусор на сложных запросах | **Корректирующий RAG (CRAG)**: данные оцениваются 0–10; слабые результаты запускают переформулировку |
| Модели уверенно галлюцинируют неверные ответы | **Обоснованная генерация + аудит достоверности**: ответы цитируют дословные фрагменты и оцениваются на подкреплённость |
| «А оно вообще работает?» | **Оценка поиска отдельно от генерации**: recall@k / MRR / nDCG@k по золотой разметке, плюс корректность ответа, обоснованность, ссылки и доля честных отказов |
| Привязка к вендору эмбеддингов/векторной БД | **Сменные компоненты**: эмбеддинги, векторное хранилище и реранкеры скрыты за небольшими интерфейсами |

В результате получается ассистент, который снимает нагрузку с поддержки,
единообразно отвечает на вопросы по HR/регламентам и — что важно — **честно
сообщает, когда не знает ответа**, вместо того чтобы угадывать.

## Архитектура

```
                          ┌──────────────────────────────────────────────┐
   вопрос ────────────────▶  ПОИСКОВЫЙ АГЕНТ  (LLM, цикл с инструментом)    │
                          │                                                │
                          │   план → поиск → чтение оценок → коррекция →   │
                          │   повторный поиск → проверка достаточности     │
                          └───────────────┬────────────────────────────────┘
                                          │ каждый вызов `search`:
                          ┌───────────────▼────────────────────────────────┐
                          │  HyDE  →  Гибридный поиск  →  Реранк + оценка    │
                          │       (плотный ⊕ BM25, RRF)   (CRAG, 0-10)       │
                          └───────────────┬────────────────────────────────┘
                                          │ собранные данные
                          ┌───────────────▼────────────────────────────────┐
                          │  ОБОСНОВАННАЯ ГЕНЕРАЦИЯ (ограничена JSON-схемой) │
                          │  ответ + ссылки (chunk_id, дословная цитата)     │
                          └───────────────┬────────────────────────────────┘
                                          │
                          ┌───────────────▼────────────────────────────────┐
                          │  САМОПРОВЕРКА ОБОСНОВАННОСТИ → коррекция уверен. │
                          └──────────────────────────────────────────────────┘
```

### Компоненты (`atlas_rag/`)

| Модуль | Ответственность |
|---|---|
| `agent.py` | **Ядро системы** — цикл LLM с инструментом, управляющий поиском |
| `llm.py` | Единый интерфейс к LLM: провайдеры Groq и Anthropic, tool use, JSON по схеме, кеш |
| `retriever.py` | Гибридный поиск (плотный + BM25), Reciprocal Rank Fusion, смешивание HyDE |
| `reranker.py` | LLM-реранк и эвристическая оценка релевантности CRAG в одном вызове |
| `query_planner.py` | Генерация HyDE + декомпозиция сложных вопросов |
| `generator.py` | Обоснованные ответы со ссылками (ограничены JSON) + аудит достоверности |
| `embeddings.py` | Сменные эмбеддинги (sentence-transformers или локальный fallback без зависимостей) |
| `vector_store.py` | Векторное хранилище в памяти (косинус) с сохранением на диск |
| `bm25.py` | Самодостаточный разреженный индекс Okapi BM25 |
| `chunking.py` | Чанкинг с учётом структуры (заголовки/абзацы) и перекрытием |
| `ingest.py` | Загрузка документов + конвейер индексации |
| `memory.py` | Память диалога + переписывание уточняющих вопросов |
| `evaluation.py` | Метрики поиска (recall@k, MRR, nDCG@k) и оценка ответа судьёй-LLM |
| `app.py` | Фасад `AtlasRAG`, связывающий всё воедино |
| `scripts/run_ablation.py` | Абляции: золотой набор × конфигурации поиска × эмбеддеры |

## Базовая поисковая абляция

Все цифры ниже получены запуском `python scripts/run_ablation.py`; полный
отчёт, включая разбор по каждому вопросу, лежит в
[`results/ablation.md`](results/ablation.md) и `results/ablation.json`.

**Данные.** Демо-база вымышленной компании Northwind Robotics: 12 документов,
21 чанк. Золотой набор [`examples/eval_cases.json`](examples/eval_cases.json)
состоит из 39 вопросов: факты, точные токены (коды ошибок, артикулы),
многошаговые, перефразировки, сравнения и 6 вопросов, ответа на которые в базе
нет. У каждого вопроса с ответом есть дословная цитата-эталон; чанк считается
релевантным, если содержит её.

**Поиск** (33 вопроса с ответом, k = 5, без LLM, полностью воспроизводимо):

| Конфигурация | Эмбеддер | Recall@5 | MRR@5 | nDCG@5 [95% CI] |
|---|---|---|---|---|
| только BM25 | — | 0.879 | 0.824 | 0.825 [0.72–0.92] |
| только вектор | bge-small-en-v1.5 (был по умолчанию) | 0.465 | 0.294 | 0.312 [0.19–0.44] |
| гибрид RRF | bge-small-en-v1.5 (был по умолчанию) | 0.813 | 0.585 | 0.610 [0.50–0.72] |
| только вектор | multilingual-e5-small (по умолчанию) | 0.975 | 0.822 | 0.850 [0.78–0.92] |
| гибрид RRF | multilingual-e5-small (по умолчанию) | 0.955 | 0.874 | 0.883 [0.80–0.95] |
| только вектор | ru-en-RoSBERTa | 0.939 | 0.860 | 0.872 [0.78–0.95] |
| гибрид RRF | ru-en-RoSBERTa | 0.924 | 0.889 | 0.887 [0.80–0.96] |
Таблица выше относится к базовой абляции поиска без LLM. Последующие сравнения
HyDE, реранкеров и полного агента выполнялись отдельными протоколами и описаны
в актуальных отчётах в начале README. Качество ответов измерялось через RouterAI;
оценки LLM-судьи рассматриваются как вспомогательные и содержат известные ошибки.

**Что из этого следует:**

- Прежний эмбеддер по умолчанию `bge-small-en-v1.5` обучен на английском и на
  русском корпусе почти бесполезен. Хуже того, он тянет гибрид ниже чистого
  BM25: RRF доверяет обоим рейтингам, и плохой рейтинг портит хороший. Поэтому
  по умолчанию теперь стоит `intfloat/multilingual-e5-small`.
- С многоязычным эмбеддером гибрид даёт лучший MRR и nDCG, чем каждая половина
  по отдельности. BM25 проваливает перефразировки (Recall@5 = 0.50 на этом
  типе), а вектор их вытягивает; точные токены вроде `ERR-VPN-720` уверенно
  находит BM25.
- Разница между e5-small и RoSBERTa лежит внутри доверительных интервалов,
  победителя на 33 вопросах не назвать. При этом e5-small меньше (118M
  параметров против 404M) и на CPU в каждом из четырёх прогонов была в 3–9 раз
  быстрее (в последнем, который лежит в `results/`, 76 против 222 мс на
  запрос). Абсолютная задержка зависит от загрузки машины, а метрики качества
  детерминированы и совпадают во всех прогонах.

**Ограничения.** Корпус маленький (top-5 — это почти четверть базы), поэтому
абсолютные значения оптимистичны. Вопросы и разметку писал автор системы.
Доверительные интервалы получены бутстрепом по вопросам, и они широкие.

## Быстрый старт

### 1. Установка

```bash
pip install -r requirements.txt
cp .env.example .env                       # и впишите GROQ_API_KEY (или ANTHROPIC_API_KEY)
```

> **Эмбеддинги:** для семантического поиска уровня production дополнительно
> установите `pip install "sentence-transformers>=3.0"`. Без него AtlasRAG
> переключается на встроенный локальный хеширующий эмбеддер, и всё продолжает
> работать офлайн — лексический поиск через BM25 функционирует в любом случае.

### 2. Запуск сквозной демонстрации

```bash
python examples/demo.py
```

Демо загружает демонстрационную базу знаний «Northwind Robotics», отвечает на
три вопроса (включая многошаговый, требующий нескольких поисков) и запускает
оценку качества.

### 3. CLI на ваших документах

```bash
python cli.py ingest path/to/your/docs      # построить и сохранить индекс
python cli.py ask "Какое у нас окно возврата для корпоративных клиентов?"
python cli.py chat                           # интерактивный диалог
python cli.py eval examples/eval_cases.json  # оценить на тестовом наборе
```

### 4. Оценка и абляции

```bash
python scripts/run_ablation.py               # таблица конфигураций → results/
python cli.py ablate --skip-llm              # то же через CLI, только поиск без LLM
pytest                                       # тесты метрик и золотой разметки
```

Без ключа LLM-провайдера скрипт измеряет конфигурации без LLM, а остальные
помечает «не измерено». Индексация и поиск ключа не требуют. Ответы LLM
кешируются в `results/raw/llm_cache.jsonl`: если прогон остановился на лимите
бесплатного тарифа, повторный запуск продолжит с того же места.

### 5. Использование как библиотеки

```python
from atlas_rag import AtlasRAG, Settings

rag = AtlasRAG(Settings())
rag.ingest_path("examples/sample_docs")

result = rag.ask(
    "Мы используем манипуляторы NW-200 на тарифе Enterprise. Какой у нас лимит "
    "запросов к API и какую компенсацию мы получим, если тикет об остановке "
    "продакшена нарушит SLA?"
)
print(result.answer)
for c in result.citations:
    print(f"  - [{c.source}] {c.quote}")
print(f"уверенность={result.confidence:.0%} обоснованность={result.faithfulness:.0%}")
```

Многоходовый диалог:

```python
chat = rag.conversation()
chat.ask("Сколько отпускных дней у сотрудников после 6 лет?")
chat.ask("А у подрядчиков так же?")   # уточняющий вопрос разрешается автоматически
```

## Конфигурация

Все настройки находятся в `atlas_rag/config.py` (`Settings`) и задаются через
аргументы конструктора или переменные окружения. Основные:

| Настройка | По умолчанию | Назначение |
|---|---|---|
| `llm_provider` / `ATLAS_LLM_PROVIDER` | `groq` | `groq` \| `anthropic` |
| `model` / `ATLAS_MODEL` | `openai/gpt-oss-120b` | Агент и генерация ответа |
| `fast_model` / `ATLAS_FAST_MODEL` | `openai/gpt-oss-20b` | HyDE, декомпозиция, реранк, проверка обоснованности |
| `judge_model` / `ATLAS_JUDGE_MODEL` | `qwen/qwen3.8-27b` | Судья при оценке (другое семейство моделей) |
| `embedding_backend` | `auto` | `auto` \| `sentence-transformers` \| `hashing` |
| `embedding_model` / `ATLAS_EMBEDDING_MODEL` | `intfloat/multilingual-e5-small` | Модель эмбеддингов (выбрана по абляции, см. «Результаты») |
| `retrieval_mode` | `hybrid` | `hybrid` \| `dense` \| `sparse` |
| `use_hyde` | `True` | Hypothetical Document Embeddings |
| `use_reranker` | `True` | LLM-реранк + оценка CRAG |
| `max_agent_steps` | `4` | Бюджет поисков на один вопрос |
| `fused_top_k` / `rerank_top_k` | `10` / `5` | Ширина воронки кандидатов |

## Заметки по дизайну и точки расширения

- **Замена векторного хранилища** на FAISS / pgvector / Qdrant — реализуйте тот
  же интерфейс `add` / `search` / `get` в `vector_store.py`. RRF использует
  только ранги, поэтому ничего ниже по конвейеру менять не нужно.
- **Замена эмбеддингов** через `embeddings.py` — подойдёт любая модель,
  возвращающая L2-нормализованные векторы.
- **Добавление инструментов** агенту (например, живой `web_search`, SQL-запрос,
  поиск в системе тикетов) — расширьте список инструментов в `agent.py`; логика
  корректирующего RAG автоматически применится и к этим источникам.
- **Тюнинг поиска** на `examples/eval_cases.json` через
  `python scripts/run_ablation.py` (поиск) и `python cli.py eval` (ответы)
  перед выкаткой изменений промптов или чанкинга.

## Примечания

- Индекс запоминает, каким эмбеддером он построен. После смены
  `ATLAS_EMBEDDING_MODEL` нужно заново выполнить `python cli.py ingest`, иначе
  `load()` откажется загружать старый индекс.
- API без состояния на каждом вызове; состояние диалога хранится на стороне
  клиента в `memory.py`.
- Оценка, генерация и проверка достоверности используют структурированный вывод,
  ограниченный JSON-схемой, поэтому разбор никогда не зависит от хрупкого парсинга
  строк.
- Весь вывод в консоль безопасен для UTF-8: ответы модели с тире и типографскими
  кавычками корректно отображаются даже в терминалах Windows.
# Проверка семантической поддержки и наблюдений агента

Дополнительные проверки во время человеческой разметки:
`python -m scripts.run_next_checks` — локальный fuzz цитат, ретроспективная
симуляция эскалации и устойчивость поиска; `python -m scripts.run_alias_probe`
— локальный кандидат восстановления технических кодов. Они не вызывают LLM.
`python -m scripts.run_alias_end_to_end` проверяет только два известных
случая через полный одиночный проход и использует прежний общий бюджет/кеш;
возобновление — `scripts.resume_routerai_eval --task alias`. Результаты —
`results/offline_checks/findings.md`. Нормализатор и адаптивный маршрут
остаются экспериментами, пакет ручной проверки не меняется.

Проверка порядка финального контекста и точных цитат:
`scripts.resume_routerai_eval --task citations`, результаты в
`results/context_citations`. Режим `context_selection="anchored_score"`
сохраняет тот же состав опор, но сортирует их по score. Цитаты по умолчанию
формируются из координат исходного текста (`citation_mode="unit_parts"`);
длинный допустимый диапазон разбивается на точные цитаты до 25 слов с
сохранением всех слов. `"units"` сохраняет первоначальный строгий режим,
`"free"` — свободный текст для контролируемого сравнения. Неверные ID и
границы отклоняются и учитываются отдельно от принятых цитат.

В исходном опыте строгий режим отклонил 14 допустимых по координатам диапазонов
из-за длины. Исправление проверяется отдельно через `scripts.replay_citation_parts`
на том же кеше без новых генераций. Исходные результаты и код зафиксированы
в `frozen_code_v1`, расширение протокола — в `citation_parts_protocol.json`.

После завершения `scripts.build_human_review` создаёт автономный документ
`human_review.html` с 24 заданиями и инструкцией. Человеческие метки не
подставляются из модели. `private_review_plan.json` и модельные отчёты
проверяющему до разметки читать не следует. Проверка интерфейса:
`python -m scripts.check_review_ui` (только учебный набор);
`python -m scripts.check_review_ui --document results/context_citations/human_review.html`
(готовый документ, без заполнения оценок). Необязательная зависимость —
`requirements-review.txt`, используется установленный Edge.

04.11.2026 пользователь разрешил выполнить разметку ассистенту. Отдельная версия
лежит в `results/assistant_review`: [разметка с источниками](results/assistant_review/annotated_review.html),
[разбор оценщика](results/assistant_review/findings.md). Это ассистентская проверка
разработчика, а не независимые человеческие метрики; исходный пакет не менялся.
`scripts.run_assistant_review` фиксирует решения до вызовов прежнего Qwen v2;
метки не передаются модели, извлечение фактов запускается без готового разбиения.
`scripts.finalize_assistant_review` собирает отчёт без API, а
`scripts.check_assistant_review` проверяет HTML и исходные payload-хеши.

Сборка контекста теперь защищает фрагмент с сущностью вопроса и лучший
результат последнего шага перед заполнением остальных мест. Настройка
`context_selection="legacy"` возвращает прежний отбор по общему score.
Выбранные ID записываются в `RetrievalTrace.selected_context_ids`, чтобы
оценка использовала ровно контекст генератора.

Сценарный проверяющий `atlas_rag.semantic_support_v2` получает вопрос и
сохраняет условия в фактах; исходный проверяющий v1 остаётся доступен.
Два исправления проверяются через `scripts.run_repair_eval` и
`scripts.resume_routerai_eval --task repairs`. Результаты и протокол —
`results/repair_v2`; старые ответы не перезаписываются. Генерация повторяется
только на 12 сохранённых последовательных траекториях, поиск не повторяется.
Итоги: [два исправления и оставшиеся ограничения](results/repair_v2/findings.md).

Завершённые метрики и разбор ограничений: [отчёт](results/validation/findings.md),
[машиночитаемая сводка](results/validation/summary.json). На реальных составных
ответах обнаружены ошибки семантического оценщика; его оценки пока не являются
автоматической гарантией обоснованности.

Экспериментальные проверки находятся в `scripts.run_validation_eval`:
40 размеченных ассистентом пар «источник — утверждение» (20 для настройки,
20 из других разделов для отложенной проверки), полный контекст агента на
39 исходных вопросах, 12 синтетических задач на последовательный поиск
с действующими/архивными нормативами и 6 диалогов с уточнением.
Разметка не прошла независимую человеческую проверку.

`Settings.agent_preview_chars=None` передаёт агенту полный текст найденных
фрагментов. Значение по умолчанию остаётся 500. Экспериментальный проверяющий
`atlas_rag.semantic_support` выделяет утверждения отдельно от проверки,
различает поддержку, противоречие и нехватку данных. Ссылки на строки и
смещения проверяются кодом; ответы и прежние оценки не исправляются.
Производственная проверка faithfulness остаётся прежней.

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-nli.txt
.\.venv\Scripts\python.exe -m scripts.run_local_nli
.\.venv\Scripts\python.exe -m scripts.run_validation_eval --phase pilot
.\.venv\Scripts\python.exe -m scripts.resume_routerai_eval --task validation
```

Запускайте только один платный процесс одновременно. Используются общий
`results/raw/routerai/usage.jsonl`, прежний кеш и исходный бюджет; результаты
сохраняются по одному кейсу в `results/validation`. Локальная NLI-проверка
API не вызывает и может работать параллельно. Она загружает модель
`MoritzLaurer/mDeBERTa-v3-base-mnli-xnli`; порог выбирается только по
настроечной половине, вероятности softmax не считаются калиброванными.
Точные цитаты, семантическая поддержка, правильность ответа и полнота поиска
считаются раздельно. Наличие эталонного числа в синтетическом ответе — только
вспомогательная проверка, не полноценная correctness.
