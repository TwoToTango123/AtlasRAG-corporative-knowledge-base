# AtlasRAG — агентный RAG для корпоративной базы знаний

AtlasRAG превращает массив корпоративных документов (регламенты, спецификации,
SLA, инструкции, договоры) в надёжного ассистента для ответов на вопросы. В
основе системы — **поисковый агент на базе LLM**: вместо жёсткого конвейера
«эмбеддинг → top-k → подстановка в промпт» Claude сам планирует и
*корректирует* свой поиск — раскладывает вопрос на части, переформулирует слабые
запросы, оценивает найденные данные и решает, когда их достаточно для ответа.
Каждый ответ снабжается **ссылками на источники** и проходит **самопроверку на
обоснованность** для защиты от галлюцинаций.

Работает на **Claude Opus 4.8** (`claude-opus-4-8`) для рассуждений и
**Claude Haiku 4.5** для массовых задач оценки. Ассистент отвечает на русском
языке.

---

## Зачем это бизнесу

| Проблема наивного RAG | Что делает AtlasRAG |
|---|---|
| Один эмбеддинг-поиск упускает точные токены (артикулы, коды ошибок) или перефразировки | **Гибридный поиск**: плотные эмбеддинги + BM25, объединённые через Reciprocal Rank Fusion |
| Один проход поиска не отвечает на составные вопросы | **Агентный цикл**: модель выполняет несколько целевых поисков и объединяет результаты |
| Поиск молча возвращает мусор на сложных запросах | **Корректирующий RAG (CRAG)**: данные оцениваются 0–10; слабые результаты запускают переформулировку |
| Модели уверенно галлюцинируют неверные ответы | **Обоснованная генерация + аудит достоверности**: ответы цитируют дословные фрагменты и оцениваются на подкреплённость |
| «А оно вообще работает?» | **Встроенная оценка качества**: корректность / обоснованность / качество ссылок на вашем наборе тестов |
| Привязка к вендору эмбеддингов/векторной БД | **Сменные компоненты**: эмбеддинги, векторное хранилище и реранкеры скрыты за небольшими интерфейсами |

В результате получается ассистент, который снимает нагрузку с поддержки,
единообразно отвечает на вопросы по HR/регламентам и — что важно — **честно
сообщает, когда не знает ответа**, вместо того чтобы угадывать.

## Архитектура

```
                          ┌──────────────────────────────────────────────┐
   вопрос ────────────────▶  ПОИСКОВЫЙ АГЕНТ  (Claude, цикл с инструментом) │
                          │                                                │
                          │   план → поиск → чтение оценок → коррекция →   │
                          │   повторный поиск → проверка достаточности     │
                          └───────────────┬────────────────────────────────┘
                                          │ каждый вызов `search`:
                          ┌───────────────▼────────────────────────────────┐
                          │  HyDE  →  Гибридный поиск  →  Реранк + оценка    │
                          │       (плотный ⊕ BM25, RRF)   (CRAG, 0-10)       │
                          └───────────────┬────────────────────────────────┘
                                          │ собранные данные
                          ┌───────────────▼────────────────────────────────┐
                          │  ОБОСНОВАННАЯ ГЕНЕРАЦИЯ (ограничена JSON-схемой) │
                          │  ответ + ссылки (chunk_id, дословная цитата)     │
                          └───────────────┬────────────────────────────────┘
                                          │
                          ┌───────────────▼────────────────────────────────┐
                          │  САМОПРОВЕРКА ОБОСНОВАННОСТИ → коррекция уверен. │
                          └──────────────────────────────────────────────────┘
```

### Компоненты (`atlas_rag/`)

| Модуль | Ответственность |
|---|---|
| `agent.py` | **Ядро системы** — цикл Claude с инструментом, управляющий поиском |
| `retriever.py` | Гибридный поиск (плотный + BM25), Reciprocal Rank Fusion, смешивание HyDE |
| `reranker.py` | LLM-реранк (как cross-encoder) **и** оценка релевантности CRAG в одном вызове |
| `query_planner.py` | Генерация HyDE + декомпозиция сложных вопросов |
| `generator.py` | Обоснованные ответы со ссылками (ограничены JSON) + аудит достоверности |
| `embeddings.py` | Сменные эмбеддинги (sentence-transformers или локальный fallback без зависимостей) |
| `vector_store.py` | Векторное хранилище в памяти (косинус) с сохранением на диск |
| `bm25.py` | Самодостаточный разреженный индекс Okapi BM25 |
| `chunking.py` | Чанкинг с учётом структуры (заголовки/абзацы) и перекрытием |
| `ingest.py` | Загрузка документов + конвейер индексации |
| `memory.py` | Память диалога + переписывание уточняющих вопросов |
| `evaluation.py` | Офлайн-оценка качества судьёй-LLM |
| `app.py` | Фасад `AtlasRAG`, связывающий всё воедино |

## Быстрый старт

### 1. Установка

```bash
pip install -r requirements.txt
export ANTHROPIC_API_KEY=sk-ant-...        # или скопируйте .env.example → .env
```

> **Эмбеддинги:** для семантического поиска уровня production дополнительно
> установите `pip install "sentence-transformers>=3.0"`. Без него AtlasRAG
> переключается на встроенный локальный хеширующий эмбеддер, и всё продолжает
> работать офлайн — лексический поиск через BM25 функционирует в любом случае.

### 2. Запуск сквозной демонстрации

```bash
python examples/demo.py
```

Демо загружает демонстрационную базу знаний «Northwind Robotics», отвечает на
три вопроса (включая многошаговый, требующий нескольких поисков) и запускает
оценку качества.

### 3. CLI на ваших документах

```bash
python cli.py ingest path/to/your/docs      # построить и сохранить индекс
python cli.py ask "Какое у нас окно возврата для корпоративных клиентов?"
python cli.py chat                           # интерактивный диалог
python cli.py eval examples/eval_cases.json  # оценить на тестовом наборе
```

### 4. Использование как библиотеки

```python
from atlas_rag import AtlasRAG, Settings

rag = AtlasRAG(Settings())
rag.ingest_path("examples/sample_docs")

result = rag.ask(
    "Мы используем манипуляторы NW-200 на тарифе Enterprise. Какой у нас лимит "
    "запросов к API и какую компенсацию мы получим, если тикет об остановке "
    "продакшена нарушит SLA?"
)
print(result.answer)
for c in result.citations:
    print(f"  - [{c.source}] {c.quote}")
print(f"уверенность={result.confidence:.0%} обоснованность={result.faithfulness:.0%}")
```

Многоходовый диалог:

```python
chat = rag.conversation()
chat.ask("Сколько отпускных дней у сотрудников после 6 лет?")
chat.ask("А у подрядчиков так же?")   # уточняющий вопрос разрешается автоматически
```

## Конфигурация

Все настройки находятся в `atlas_rag/config.py` (`Settings`) и задаются через
аргументы конструктора или переменные окружения. Основные:

| Настройка | По умолчанию | Назначение |
|---|---|---|
| `model` / `ATLAS_MODEL` | `claude-opus-4-8` | Основная модель рассуждений |
| `fast_model` / `ATLAS_FAST_MODEL` | `claude-haiku-4-5` | Оценка / декомпозиция |
| `embedding_backend` | `auto` | `auto` \| `sentence-transformers` \| `hashing` |
| `use_hyde` | `True` | Hypothetical Document Embeddings |
| `use_reranker` | `True` | LLM-реранк + оценка CRAG |
| `max_agent_steps` | `6` | Бюджет поисков на один вопрос |
| `fused_top_k` / `rerank_top_k` | `10` / `5` | Ширина воронки кандидатов |

## Заметки по дизайну и точки расширения

- **Замена векторного хранилища** на FAISS / pgvector / Qdrant — реализуйте тот
  же интерфейс `add` / `search` / `get` в `vector_store.py`. RRF использует
  только ранги, поэтому ничего ниже по конвейеру менять не нужно.
- **Замена эмбеддингов** через `embeddings.py` — подойдёт любая модель,
  возвращающая L2-нормализованные векторы.
- **Добавление инструментов** агенту (например, живой `web_search`, SQL-запрос,
  поиск в системе тикетов) — расширьте список инструментов в `agent.py`; логика
  корректирующего RAG автоматически применится и к этим источникам.
- **Тюнинг поиска** на `examples/eval_cases.json` через `python cli.py eval`
  перед выкаткой изменений промптов или чанкинга.

## Примечания

- API без состояния на каждом вызове; состояние диалога хранится на стороне
  клиента в `memory.py`.
- Оценка, генерация и проверка достоверности используют структурированный вывод,
  ограниченный JSON-схемой, поэтому разбор никогда не зависит от хрупкого парсинга
  строк.
- Весь вывод в консоль безопасен для UTF-8: ответы модели с тире и типографскими
  кавычками корректно отображаются даже в терминалах Windows.
