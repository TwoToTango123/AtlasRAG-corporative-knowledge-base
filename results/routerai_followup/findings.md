# Итоги двух дополнительных экспериментов

Завершены два новых прогона по 39 вопросов и 156 перепроверок сохранённых ответов.
Полные агентные ответы из предыдущего эксперимента не генерировались заново.
Во всех трёх сравниваемых схемах генератор — DeepSeek Flash, вспомогательная
модель — GPT-OSS 20B. Новый Qwen-оценщик не видел названий моделей, схем и прежних
баллов, но получил вопрос, эталон, ответ, цитаты и реально переданные генератору
источники. Шесть контрольных примеров пройдены.

## Один поиск против полного агента

| Метрика | Полный агент | Один поиск без HyDE | Один поиск с HyDE |
|---|---:|---:|---:|
| Правильность, новый оценщик | 0,926 | 0,939 | 0,939 |
| Recall@5 | 1,000 | 1,000 | 0,985 |
| MRR@5 | 0,985 | 0,965 | 0,965 |
| nDCG@5 | 0,986 | 0,974 | 0,966 |
| Обоснованность, новый оценщик | 0,933 | 0,939 | 1,000 |
| Дословность цитат, проверка кодом | 100% | 100% | 100% |
| Верные отказы по флагу результата | 6/6 | 6/6 | 6/6 |
| Ошибочные отказы по флагу результата | 1/33 | 1/33 | 2/33 |
| Поисков на вопрос | 3,46 | 1 | 1 |
| Время успешного кейса, с | 37,8 | 13,5 | 10,2 |

На этом демонаборе дополнительная сложность агента не показала выигрыша в
правильности ответа. Полный агент немного лучше ранжирует найденное, однако
один поиск без HyDE тоже покрывает все эталонные сведения. HyDE не улучшил
среднюю оценку правильности и немного снизил Recall. Для следующей итерации
разумная исходная схема — один гибридный поиск, реранкинг и генерация без HyDE.
Рабочая конфигурация проекта в рамках этого эксперимента не переключалась.

Разницу 0,014 в правильности нельзя считать доказанным преимуществом:
парный bootstrap 95% для разницы «один поиск без HyDE минус агент» даёт
[-0,077; 0,100] на 33 вопросах. Для HyDE минус без HyDE: [-0,092; 0,091].
Это оценка неопределённости на данном наборе, без повторных генераций.

В простом варианте три продукционных LLM-вызова на вопрос: реранкер, генератор
и аудит обоснованности. HyDE добавляет четвёртый. У полного агента дополнительно
работают декомпозиция и ходы планировщика, а HyDE и реранкер вызываются для
каждого поиска. Оценщик эксперимента — отдельный дополнительный вызов.
Кеш и повторы влияют на фактическое число оплаченных запросов.

Времена нельзя трактовать как чистое сравнение скорости: они зависят от кеша,
сетевых пауз и восстановлений, а в ранних полных прогонах включали прежнего
оценщика. В новых схемах оценка с источниками выполнялась отдельным этапом.
Поэтому даже результат «с HyDE быстрее» не доказывает преимущество HyDE по скорости.

## Проверка оценщика

| Сохранённые ответы | Правильность прежде → с источниками | Обоснованность прежде → с источниками |
|---|---:|---:|
| Полный GPT-OSS 120B | 0,848 → 0,906 | 0,879 → 0,967 |
| Полный DeepSeek | 0,912 → 0,926 | 0,879 → 0,933 |

Ответы не менялись. Изменились контекст и критерии аудита; обоснованность прежде
оценивала GPT-OSS 20B, теперь — Qwen. Рост балла не является улучшением системы.
Прежние оценки правильности для новых схем не усредняются: исходный оценщик
дважды возвращал обрезанный JSON, после чего сравнение переведено на единый
новый аудит всех четырёх групп. Подробности интеграционных исправлений есть
в run_notes.md. Стоимость неудачных попыток учтена.

Важная находка: успешное прохождение шести контролей не гарантирует надёжности
оценщика на реальных ответах. В judge_audit.json сохранены четыре проверенных
примера, где все ID и цитаты действительно присутствуют в переданном контексте,
но Qwen дал ноль за цитирование. Например, full_deepseek/q04 ошибочно объявляет
ID вымышленными, q02 штрафует за Markdown, хотя промпт разрешает такие отличия,
а single_hyde/q18 содержит объяснение, признающее цитаты верными, при нулевом балле.
Хеши восстановленных входов совпали с сохранёнными хешами запросов оценщика.

Дословность следует проверять кодом, а семантическую поддержку утверждений —
отдельно, с выборочной ручной проверкой. LLM-баллы остаются оценками, не истиной.
Исходные баллы и ответы не исправлялись, в том числе при явном противоречии
балла и объяснения.

Определение отказа также влияет на метрику. По флагу answer_found=false у агента
и варианта без HyDE по одному ошибочному отказу, с HyDE — два. По семантической
разметке нового оценщика соответственно 0, 0 и 1: частичный ответ может иметь
флаг answer_found=false и не быть полным отказом. Эти определения не смешиваются.

## Расходы и ограничения

Эти два эксперимента дополнительно израсходовали 909 863 зарегистрированных
входных и выходных токена и фактически 3,7276 ₽. Остаток — 91,2411 ₽; весь
накопленный расход с исходных 100 ₽ составляет 8,7589 ₽. Суммы сверены с балансом.
Резервы в budget_used_rub после сетевых ошибок не являются списаниями.

Корпус небольшой: 12 документов, 21 чанк, 33 вопроса с ответом и шесть без ответа.
Выводы не переносятся автоматически на большую корпоративную базу. Остальные
предложенные эксперименты — расширение корпуса, BGE в агенте и повторные прогоны —
не запускались.
