# Замечания к выполнению

На первом фоновом запуске исходный Qwen-оценщик вернул обрезанный JSON при
лимите 512 выходных токенов. Для продолжения новых однопроходных экспериментов
лимит этого оценщика поднят до 1024 через `Settings.judge_max_tokens`.
Промпт, схема оценивания и модель не менялись. Ответы генератора не исправлялись.
Успешные ранее сохранённые кейсы остались прежними; отдельные начальные оценки
могли быть получены с лимитом 512. В прежних полных прогонах лимит также был 512.
Новый оценщик с источниками с самого начала имеет лимит 1024.

После повторного обрезания исходного оценщика уже при лимите 1024 его вызовы
для новых кейсов прекращены. Это не меняет генерацию ответов, поиск или аудит
обоснованности. Сравнение правильности всех четырёх групп выполняется одним
и тем же новым оценщиком с источниками. Ранние исходные оценки сохранены в
отдельных кейсах, но их неполное среднее для однопроходных групп не выводится.
Для остальных новых кейсов исходные correctness/citation_quality равны null,
а не нулю. Детерминированные поисковые метрики продолжают считаться для всех.

Во время перепроверки сохранённых ответов RouterAI вернул пустой необязательный
объект `usage.completion_tokens_details`, который строгая схема SDK Groq отклонила.
Адаптер теперь разбирает текст ответа отдельно от статистики: исходные токены и
стоимость по-прежнему учитываются непосредственно из ответа RouterAI. Успешные
перепроверки сохранены, повторяется только незавершённый кейс. Исправление
проверено отдельным тестом; ответы генераторов не менялись.

Одна перепроверка вернулась как JSON-массив с единственным полным объектом
оценок вместо объекта верхнего уровня. Добавлена обработка только такой
однозначной обёртки без изменения баллов. Сохранённый ответ использован из
кеша, повторный платный вызов для исправления этой обёртки не требуется.
